# Bug hunt report — 2026-08-02

Deep adversarial review of the full tbctl stack: backend core + hardware layer,
firing/sequencer/safety path, REST/WS API + recorder, config/codegen, on-device
Lua sequencer, frontend data layer, frontend components, and tests/CI/deploy.
Conducted with eight parallel review passes, cross-checked against each other;
findings marked **[verified]** were confirmed by executing code or by direct
line-level tracing in this session (several independently rediscovered by two
or three separate passes). No fixes applied — report only.

Baseline at review time: `uv run pytest` → 178 passed, 2 skipped;
`ruff check .` clean; `tbctl codegen --check` ok; `tbctl validate` ok;
both Lua harnesses pass (8/8 CRC vectors, 48/48 sequencer checks).
**Everything below is invisible to the current green suite.**

Severity legend: **CRIT** = can produce an unsafe physical state or defeat a
safety layer; **HIGH** = wrong behavior with serious operational impact;
**MED** = real bug, bounded impact; **LOW** = minor/edge. Confidence is stated
per finding.

## 1. Critical — safety-path defects

### C1. Single CMD mailbox: FIRE can clobber an in-flight redline ABORT, and the redline latch never retries [verified]
- `src/tbctl/services/sequencer.py:226-241`, `src/tbctl/services/redlines.py:82-121`, `lua/sequencer_main.lua:80-98`
- All commands share one u16 register (`CMD`), consumed once per 1 ms Lua tick,
  last-writer-wins. There is no lock serializing `SequencerService` operations
  and `abort()` is a single write with **no verification** that the device ever
  consumed it. If a redline trips (writes `CMD=ABORT`) while an operator
  `/sequences/fire` is in flight (state still reads ARMED), the FIRE write can
  land after the ABORT write but before the next Lua tick — the abort is
  silently lost and the engine fires. `RedlineWatcher._tripped` is a one-shot
  latch: after the lost abort, host-side redline protection is **dead for the
  rest of the burn**.
- A second, independent race on the device side: Lua reads `CMD` then writes 0
  to clear it (`sequencer_main.lua:81-83`); a host ABORT landing in that
  sub-ms window is erased.
- Confidence: mechanism confirmed by tracing (both sides); window is narrow.
  The mock processes CMD synchronously inside `write_name`
  (`src/tbctl/hw/ljm_mock.py:427-430`), so **no test can ever exhibit this**.

### C2. A crashed Lua interpreter mid-burn defeats every software safety layer while `/abort` still returns ok
- `src/tbctl/services/sequencer.py:238-241`, `src/tbctl/api/rest.py:302-306`, `src/tbctl/hw/watchdog.py`, `src/tbctl/api/ws.py:90-97`
- No host-side liveness check on the interpreter. USER_RAM registers persist
  after a Lua crash, so `state()` returns ARMED/RUNNING forever and
  `watch_terminal` never fires. The T7 hardware watchdog is reset by *any*
  host communication — and the host keeps streaming AIN data — so it never
  trips either. The layer that died (Lua heartbeat consumer) was the one
  meant to catch this. Valves freeze at the last-applied mid-burn word;
  operator abort writes into a dead mailbox and the endpoint unconditionally
  returns `{"ok": true}`. Only the hardwired E-stop remains.
- T7 Lua OOM crashes are a documented reality in this repo
  (`lua/sequencer_main.lua:31-33`, `docs/t7-lua-stream-fixes.md`).
- Suggested direction: watch a Lua-alive counter (e.g. `ELAPSED_MS`) while
  armed/running; make `abort()` verify the state transition and escalate
  (direct safe-word `DIO_STATE` write, stop feeding stream/comm so the HW
  watchdog can fire) when it doesn't happen.
- Confidence: architectural, confirmed by tracing; low probability,
  catastrophic consequence.

### C3. Lua bad-table FAULT path writes DIO_STATE before DIO_INHIBIT has ever been programmed [verified]
- `lua/sequencer_main.lua:72` (failure branch) vs `:71` (success branch is the only place `DIO_INHIBIT`/`DIO_DIRECTION` are written)
- On the first LOAD after boot, a rejected table takes the FAULT branch and
  writes `DIO_STATE = U.w` where `U.w` is still the boot value **0**, with the
  device inhibit mask still at its power-on default (0 = nothing inhibited).
  That drives all DIO lines low as outputs — not the configured safe word, and
  including non-sequencer lines. The shipped config's safe word happens to be
  0x0000, masking this; any bench where some valve's safe electrical level is
  1 (`fail_safe: open` + `open_state: high`, etc.) gets that valve driven to
  the *unsafe* level on a corrupted first upload.
- The mock boots with `dio_inhibit=0xFFFF` (`src/tbctl/hw/ljm_mock.py:75`),
  the opposite of hardware, so tests cannot catch this.
- Related: the FAULT branch also publishes the *previous* table's
  CRC16/STEP_COUNT telemetry (stale identity during incident triage).
- Confidence: code path confirmed; impact depends on T7 power-on inhibit
  default (documented as 0).

### C4. Failed load verification desyncs host and device: UI shows sequence A, device holds B, confirm string arms B [verified]
- `src/tbctl/services/sequencer.py:112-176` (`self.loaded` updated only at the end, after upload + verify), `:196-224`
- `load(B)` replaces the device table (device reaches LOADED), then performs
  two more register reads for verification. Any exception in that window (a
  transient LJM read failure suffices) leaves `self.loaded = A` while the
  device holds **B**. `arm(confirm="A")` then passes the confirm check,
  checks A's preconditions, arms A's redlines — and the device fires B's
  steps. Fix direction: invalidate `self.loaded` before upload begins, or
  command RESET on any verify failure.
- Confidence: confirmed by tracing.

### C5. Model-valid channels.yaml can brick the node: hot-apply persists the file, kills acquisition, and startup crashes [verified by execution]
- `src/tbctl/services/config_editor.py:71-96`, `src/tbctl/services/acquisition.py:186-192`, `src/tbctl/config/models.py:214-251` (no rate-divisibility check), `src/tbctl/node.py:197-206` (catches only `ConfigError`)
- Rate-group divisibility ("rate_hz must divide the stream rate") is enforced
  only inside `AcquisitionService._configure`, not in
  `validate_channels_payload`. `apply_channels` writes the YAML to disk
  *before* applying; when `acq.reconfigure()` then raises `ValueError`:
  1. HTTP 500 with acquisition **stopped and never restarted** (line 85 never
     reached) — telemetry, recording, redline evaluation all dead;
  2. the bad file is persisted, so the next node start raises an uncaught
     `ValueError` and the process crashes until someone hand-restores from
     `.backups`. This violates the module's own "nothing is persisted unless
     the new map validates" contract.
- Reproduced by execution: `rate_groups: {default: 50, odd: {rate_hz: 7}}`
  passes `ChannelMap.model_validate`, then `_configure` raises.
- Same non-transactional shape in `apply_sequence`/`apply_pid`: raw client
  `payload` is written (not the validated model's dump), before the apply
  steps that can fail. Independently found by three review passes.
- Confidence: confirmed by execution.

### C6. NaN silently disables redlines and ARM preconditions — and resets the persist debounce [verified by execution]
- `src/tbctl/services/redlines.py:91-97`, `src/tbctl/services/sequencer.py:186-194`, `src/tbctl/services/acquisition.py:295-304`, `src/tbctl/config/expr.py`
- Both checks are plain `v < min` / `v > max`; NaN compares false to
  everything, so a NaN sample is always "in bounds". Derived channels produce
  NaN **by design** on expression failure (swallowed exception → NaN column,
  only a log line) and on domain errors (`log`/`sqrt` of negatives — only a
  RuntimeWarning). A redline or precondition on such a channel arms
  "successfully" and can never trip. Additionally, in `_on_block` a NaN sample
  takes the `not violated` branch and **resets the persistence streak**, so an
  intermittently-NaN sensor defeats a real violation's `persist_ms` debounce.
- Confidence: confirmed by execution of the comparison semantics; independently
  found by two passes.

## 2. High severity

### H1. One slow/stalled WebSocket client freezes telemetry for all clients and stalls terminal-state handling
- `src/tbctl/api/ws.py:90-119`
- `_emit_loop` iterates clients sequentially with `await c.send(f)` — no
  timeout, no per-client queue, no drop policy. A client that stops reading
  fills its TCP buffer and blocks the loop; all other operator consoles stop
  receiving frames/status, and `sequencer.watch_terminal()` (called at the top
  of the same loop) stops running, delaying heartbeat teardown/redline disarm
  on terminal states. Fix shape: bounded per-client queue + writer task,
  drop-or-disconnect on overflow. Confidence: confirmed by tracing.

### H2. Recorder flush loop dies silently on any I/O error → unbounded memory growth and a run that can never be stopped
- `src/tbctl/services/recorder.py:191-218` (`_flush_loop` has no try/except), `:149-161` (`stop_run` re-flushes)
- Disk-full or any HDF5 error kills the flush task permanently; acquisition
  keeps appending to `self._pending` in RAM without bound. `stop_run` then
  re-raises the same error from its own final `_flush`, so the run never
  closes, `self._run` stays set, and every future `/api/runs/start` 409s
  ("already recording") until process restart. Confidence: confirmed by tracing.

### H3. `POST /api/connection/deploy-lua` permanently kills acquisition; a failed deploy leaves the HW watchdog silently disabled
- `src/tbctl/hw/script_loader.py:95-109`, `src/tbctl/api/rest.py:889-910`
- `release_shared_ram` calls `iface.stream_stop()` against the live device;
  nothing restarts acquisition, so `_run` retries forever on a dead stream
  while `acq.running` still reports True. Separately, the deploy's first
  action writes `WATCHDOG_ENABLE_DEFAULT = 0`; `configure_watchdog` is only
  reached on the success path — on `ScriptLoadError` (→502) or an uncaught
  `DeviceError` from `reboot()` (→500), safety layer 2 stays disabled with no
  event, no alert, and the node keeps operating. Confidence: confirmed by tracing.

### H4. Runtime device switch and channel hot-apply never re-arm the watchdog or re-verify the interpreter
- `src/tbctl/services/device_manager.py:154-185`, `src/tbctl/services/config_editor.py:71-96` vs `src/tbctl/node.py:140-146`
- `configure_watchdog`/`check_interp_version` run only in the startup lifespan
  (and only when not `--sim`). A node started in sim and switched to hardware
  at runtime gets neither. Worse: `apply_channels` hot-applies a new
  `safe_word()`/`dio_inhibit()` to every service *except* the hardware
  watchdog — after changing a valve's `fail_safe` or DIO bit, a comms-loss
  watchdog trip drives the **old** fail-safe DIO image on the wrong bits,
  during a fault. Independently found by two passes. Confidence: confirmed by tracing.

### H5. Blocking LJM device I/O on the asyncio event loop starves the heartbeat and delays abort exactly when comms degrade
- `src/tbctl/api/ws.py:100-104` (`_seq_status` register reads inline in the emit loop), `src/tbctl/api/rest.py:290,300,316` (`state()` inline in async handlers), `src/tbctl/services/acquisition.py:263-266` (CJC `read_name` on the loop)
- On real hardware these are network/USB round-trips (seconds on LJM
  timeout/retry) executed directly on the event loop at 10 Hz. During a
  degraded link: the `HeartbeatPublisher` task can't be scheduled → device HB
  timeout aborts a *healthy* burn; the operator's `/sequences/abort` shares the
  same stalled loop and is delayed by seconds precisely when needed. Everywhere
  else the code carefully uses `asyncio.to_thread`; these sites are the
  exceptions. Related ordering flaw: `RedlineWatcher._trip` performs
  synchronous JSONL + recorder-sink writes **before** scheduling the abort
  command (`src/tbctl/services/redlines.py:103-121`) — SD-card latency adds
  directly to tank-overpressure abort latency. Confidence: confirmed by tracing.

### H6. Catch-up tick batching collapses staged abort timing; overrun during ABORTING restarts the abort table and clobbers the error code
- `lua/sequencer.lua:180-187` main loop; `U.Q` resets `t=0,i=1`; overrun gate `x>250 and (S==3 or S==5)`
- When `LJ.CheckInterval` reports a backlog, all virtual ticks run
  back-to-back: an abort started inside a catch-up batch executes its staged
  shutdown steps (fuel → ox → purge, deliberately spaced) at Modbus-write
  speed instead of real milliseconds — exactly when the system is already
  degraded. Separately, a ≥250 ms stall while *already ABORTING* re-enters
  `U.Q(5)`: the abort restarts from step 1 (re-applying early abort words out
  of context, potentially forever under repeated stalls) and the original
  abort reason (HB_TIMEOUT/SPARK_GUARD/HOST_ABORT) is overwritten with
  OVERRUN, destroying post-incident evidence. Fix shape: gate the overrun
  abort to `S==3` only; consider rate-limiting abort-step application during
  catch-up. Confidence: confirmed by tracing; found by two passes.

### H7. `bit.bnot` on T7 float32 numbers may break DIO_DIRECTION setup and spark force-low — unverifiable off-hardware
- `lua/sequencer.lua:119,159`; test shim `tests/lua/bit_compat.lua:11`
- T7 Lua numbers are single-precision floats (the code itself works around
  this at line 117). If the firmware's `bit.bnot` returns unsigned 32-bit
  results — which is what the desktop test shim models — the result is not
  float32-representable and rounds before `band`: computed concretely, inhibit
  `0xFF80` → `bnot` → rounds to `0xFFFF0000` → `DIO_DIRECTION` written as
  **0** (no controlled line configured as output; loud failure at checkout).
  The spark force-low mask suffers the same corruption. If the firmware
  returns signed int32 (LuaJIT convention), everything is exact. Nothing in
  the repo verifies which convention the deployed firmware uses; the desktop
  rig (64-bit integer Lua) is structurally incapable of catching it.
  **Needs a one-time hardware verification.** Confidence: arithmetic confirmed
  numerically; firmware branch unverified.

### H8. Frontend: a total data freeze is invisible — every value renders as live
- `frontend/src/databuf.ts:69-83`; consumers `ValueTablePanel.tsx:28`, `panels/PidPanel.tsx:81`; `Sidebar.tsx:156` (no stale check at all)
- `isStale(tag)` compares each tag's newest sample against the freshest *tag*,
  not any clock. If the whole stream stalls (device hang, stream death, WS
  drop while HTTP lives), all buffers froze at the same instant, so every tag
  is "fresh" forever. The backend keeps emitting `seq_status` regardless of
  frame flow, so the heartbeat chip stays green. Minutes-old pressures render
  styled as live — the exact failure the databuf comment promises to prevent.
  The fix needs a wall-clock (or WS-liveness) ceiling in addition to the
  relative check. NaN samples also render as the literal string "NaN" via
  `toFixed(2)`. Independently found by two passes. Confidence: confirmed by tracing.

### H9. Frontend: chart history silently discarded (seed race) and fabricated across outages (no re-backfill)
- `frontend/src/databuf.ts:37-47` (`seed`), `panels/TimeseriesPanel.tsx:108-118`, `frontend/src/ws.ts:37-41`, `src/tbctl/api/ws.py:31-35`
- `seed()` is all-or-nothing: if even one WS frame lands before the
  `fetchLive(300s)` backfill resolves (the common ordering — `connectWs()`
  runs first), the *entire* 5-minute history is dropped with no error; after
  a mid-test browser refresh the chart shows only post-load data. And after a
  WS reconnect the server streams from connect-time with no re-backfill; the
  outage gap has no null sentinels, so uPlot draws a **straight line bridging
  the gap** — fabricated-looking data an operator cannot distinguish from a
  real trend. Independently found by two passes. Confidence: confirmed by tracing.

### H10. ConnectionModal poll clobbers the operator's typed device IP every 2 s
- `frontend/src/components/ConnectionModal.tsx:22-36`
- `setInterval(refresh, 2000)` captures the first render's closure where
  `ip === ""`, so `if (!ip) setIp(i.ip)` fires on every poll, resetting the
  field to the server value. An operator typing a new Ethernet IP has it
  reverted under them; clicking ETHERNET then posts the reverted (wrong)
  address. Confidence: confirmed by tracing (stale closure, deps `[]`).

### H11. P&ID valve confirm popover can show one action while the confirming click sends the opposite
- `frontend/src/components/panels/PidPanel.tsx:56-71,94`
- The confirming click recomputes the action from *current* live state while
  the popover shows `pending.action` captured at the first click; if the
  perceived valve state flips between clicks (another client, status refresh),
  the operator confirms "open" and the UI sends "close". The confirm branch
  also skips the `canActuate` re-check (backend 409 is the only backstop).
  Confidence: confirmed by tracing.

### H12. `fire()` does not check control mode
- `src/tbctl/services/sequencer.py:226-236`, `src/tbctl/api/rest.py:292-300`
- `arm()` requires `control_enabled`; `fire()` never receives it. A crew that
  disables control mode after arming (believing the bench locked out) can
  still fire; disabling control mode while ARMED disarms nothing.
  Confidence: confirmed by tracing.

### H13. No authentication on any control endpoint
- `src/tbctl/api/rest.py` (whole router), `src/tbctl/node.py:166-178`
- Arm/fire/manual-valve/control-mode/config-write are reachable by anyone on
  the bench LAN (`0.0.0.0:8000`, plain HTTP, no origin checks — CSRF-able
  from any browser on the network). Confirm strings are not secrets and
  control mode is itself an unauthenticated toggle. Deployment docs treat the
  LAN as trusted — that assumption should at least be enforced (bind scope,
  token, or mTLS) and documented as a hard requirement. Confidence: confirmed.

### H14. LJM stream auto-recovery `-9999.0` placeholder samples pass unfiltered into calibration, recorder, and redlines
- `src/tbctl/hw/ljm_iface.py:182-186`, `src/tbctl/services/acquisition.py:258-312`
- On real hardware, eStreamRead emits `-9999.0` dummy samples during
  auto-recovery. These flow through calibration (×25 gain → −249,975 "bar")
  into ring buffers, HDF5, and the redline watcher — a `min`-bounded redline
  spuriously trips; recorded data is corrupted. The mock never produces them,
  so no test can catch it. The small 2048-byte stream buffer configured at
  `ljm_iface.py:178` makes auto-recovery *more* likely. Confidence: high
  (documented LJM behavior; unhandled in code).

## 3. Medium severity

### Backend / services

- **M1. No mutual exclusion across switch / hot-apply / deploy / run-start.**
  `rest.py:866-887` `_switch_guard` is check-then-act across awaits;
  `AcquisitionService.start()` (`acquisition.py:218-228`) blindly overwrites
  `self._task` (leaking a live `_run` task). Double-clicked switches interleave
  stop/build/open/start; a run started during `apply_channels`' stop-window
  builds an HDF5 layout from rings about to be replaced → "successful" run
  file with zero data (listener KeyErrors are swallowed). Needs one
  operational `asyncio.Lock`. [traced]
- **M2. `_ingest` outside the try in `_run`** (`acquisition.py:242-254`): any
  ingest exception kills acquisition silently and then re-raises *later* out
  of `stop()` — i.e. inside `DeviceManager.switch()`'s restore path or
  lifespan teardown, skipping `iface.close()`. [traced]
- **M3. Recorder concurrency:** `_pending` list swap between event loop and
  flush thread can drop a block; `stop_run` cancel + re-flush can run two
  `_flush` bodies concurrently against one h5py file (h5py is not
  thread-safe) → duplicate/corrupt tail (`recorder.py:149-218`). `start_run`
  has a check-then-await race: two simultaneous starts → `FileExistsError`
  500 or an orphaned first run that never closes (`recorder.py:102-147`).
  `PATCH /runs/{id}/meta` and report rerun both open the same file `r+`
  concurrently from threadpool threads (`recorder.py:253-271`,
  `review.py:137-139`). One per-run lock covers all of these. [traced]
- **M4. Annotation sidecar read-modify-write race** (`annotations.py:30-143`):
  sync endpoints run in the threadpool; concurrent writes lose annotations
  (last-writer-wins) and a reader can catch a half-written file (`_save`
  truncates in place; no temp-file rename). [traced]
- **M5. Preconditions and redlines evaluated on arbitrarily stale data.**
  `latest_values()` has no freshness check; if the stream is wedged (the
  `_run` retry loop), ARM preconditions pass on minutes-old samples and armed
  redlines silently stop evaluating (no blocks → no trips) with no event or
  alarm. Found independently by three passes.
  (`sequencer.py:178-194`, `acquisition.py:78-82,242-254`) [traced]
- **M6. `reset()` from ARMED is accepted by Python but ignored by the Lua**
  (`sequencer.py:243-252` refuses only RUNNING/ABORTING; `sequencer_main.lua:94`
  accepts RESET only from states 1/4/6/7): the host stops the heartbeat first,
  the device discards the RESET, and ~500 ms later the heartbeat monitor fires
  a full **abort-table actuation** plus a 409 timeout to the operator. There
  is no clean stand-down path from ARMED. Found by two passes. [traced]
- **M7. Manual spark has no on-time guard** (`manual_control.py:26-49`):
  `max_on_ms` (coil protection) is enforced only by the compiler (static) and
  the Lua guard (RUNNING only); a manual "on" in IDLE stays energized
  indefinitely. Found by two passes. [traced]
- **M8. MockDevice is not thread-safe** yet is called concurrently from the
  event loop, the `to_thread` stream reader, and the FastAPI threadpool
  (`ljm_mock.py:344-434`): racing `advance()` double-ticks the 1 ms sim
  (timeline jumps during sim training with a dashboard open). [traced]
- **M9. RingBuffer read/write race across threads** (`acquisition.py:37-85` +
  sync `/api/live`): after wraparound, readers can observe torn windows with
  non-monotonic `t`, breaking the `searchsorted` slicing (display/export
  impact only; redline path stays on the event loop). [traced]
- **M10. Wall-clock timebase:** sample times are `time.time()`-at-stream-start
  + index/rate (`acquisition.py:226-268`); `dropped_scans` exists but is never
  incremented, so lost scans silently shift the whole timebase (and
  `persist_ms` math). NTP steps between acq restarts create non-monotonic ring
  times; WS `frames_since` cursors can stall. [traced]
- **M11. `allow_unsafe_end` + DONE is a protection vacuum.** After DONE the
  Lua tick handler does nothing: no heartbeat check, no spark guard, ABORT is
  a silent no-op in states 4/6/7 (`sequencer_main.lua:92-93`) yet the REST
  endpoint returns ok. The compiler's spark check measures on-time only up to
  the last step's `t`, so a spark turned on **at the final step** contributes
  0 ms and compiles cleanly — both D9 layers defeated; valves can be left
  energized with zero autonomous protection. Found by two passes. [traced]
- **M12. Nothing requires the abort table to start at t=0**
  (`models.py:391-412`): an abort table beginning at `t: 0.5` leaves the
  engine in its full firing state for 500 ms during every abort, with
  heartbeat and spark guard both disabled during ABORTING. The compiler
  validates the abort *end* state but never abort *start* latency. [traced]
- **M13. WS contract: one per-client `t_last` shared across rate groups**
  (`ws.py:105-115` + `acquisition.py:336-357`): the watermark advances to the
  fastest ring's newest sample, permanently skipping any slower ring whose
  samples are ingested >1 emit interval behind. Latent until mixed-rate
  ingestion skews >100 ms. [traced]
- **M14. Regex SVG "sanitizer" is bypassable → stored XSS in the operator
  client** (`config_editor.py:166-183`): blocklist regexes miss `<style>`
  CSS, entity-encoded handlers, `<use>`/`<image href>` tricks; uploaded P&ID
  SVGs render inline in other operators' browsers. Use a real allowlist
  sanitizer or render via `<img>`/CSP-sandboxed. [traced]

### Config / validation

- **M15. `tbctl validate` and startup never *compile* sequences**
  (`cli.py:11-47`, `loader.py:137-172`): compile-only rules (final state ==
  safe word, abort ends safe, spark on-time, step spacing) surface only at
  `/sequences/{name}/load` — i.e. on test day. Sharper: flipping a valve's
  `fail_safe` in the channel editor hot-applies fine, changes `safe_word`, and
  every existing sequence then fails compile at its next load. [traced; shipped
  configs verified to compile today]
- **M16. Abort step times unbounded** (`models.py:408-412`): `max_duration_s`
  caps only the main table. `t: 5e6` in an abort step passes validation then
  raises an uncaught `TableFormatError` → HTTP 500; `3600 s < t ≤ 4.29e6 s`
  passes the entire host stack and faults on-device (`BAD_TABLE`) — the Lua's
  1-hour cap (`sequencer_main.lua:47,56`) has no host-side mirror. [verified by
  execution; found by three passes]
- **M17. Importing the loader mutates PyYAML process-wide, and written files
  are booby-trapped for standard YAML consumers** (`loader.py:40-46`): the
  subclass mutates the resolver table *inherited from `yaml.resolver.Resolver`*
  (never copied), changing `yaml.safe_load`/`safe_dump` behavior for every
  library in the process; files written by the config editor contain unquoted
  `fail_safe: off` that vanilla YAML tools read as booleans. [verified by
  execution]
- **M18. Duplicate YAML keys silently last-wins** (`loader.py`, no
  construct-time check): `set: {valve.a: open, valve.a: close}` loads as
  `close`; a duplicated `steps:` block silently discards the first table.
  Deserves a hard error in a fire-control format. [verified by execution]
- **M19. TableCal clamps silently** (`acquisition.py:127-128`): `np.interp`
  clamps outside the table domain, so a channel calibrated to 20 bar can never
  *report* more than 20 bar — a redline `max: 22.0` on it is physically
  incapable of tripping. No validation ties redline limits to the cal's
  representable range. [confirmed numpy semantics; no shipped TableCal yet]
- **M20. Review-rule `sequences:` scoping never validated**
  (`models.py:453-501`, `review.py:85-87`): renaming a sequence silently
  disables every review rule scoped to the old name — reports just shrink.
  [traced]
- **M21. Thermocouple `hw` accepts any `AIN\d+`** (`models.py:137-142`):
  `AIN9999` passes validation and fails at stream start (compounding C5's
  broken-restart mode). [verified by execution]

### Frontend

- **M22. Run-switch race clobbers chart refs across runs**
  (`TimeseriesPanel.tsx:276-330`; same pattern `RunEventsBar.tsx:33-40`): the
  run-load `Promise.all` has no cancellation; a slow run-A fetch resolving
  after a switch to run B overwrites shared refs — run B's chart draws run
  A's FIRE/abort/redline markers, annotation bands, and t0 shift; a new
  annotation saved in that state lands at the wrong epoch. Found by two

- **M23. ARM/FIRE confirm UI follows the dropdown, not the loaded sequence**
  (`SequencePanel.tsx:105-127`): load A, select B → UI offers "CONFIRM ARM

  double-click guard. [traced]
- **M24. Legend series-hide is a silent no-op in run view**
  (`TimeseriesPanel.tsx:336-345` vs `386-428`): chips gray out but the line

- **M25. Editor input hazards:** `num()` = `parseFloat(s) || 0` turns

- **M26. Initial-load failures swallowed; silent command failures:**
  `fetchChannels`/`fetchDashboards` have no `.catch` and no retry — one

- **M27. Abort sound can be silently non-functional** (`alert.ts:7-37`):

## 4. Low severity (selected)

- **L1.** Reconnect backoff resets on `onopen` before the link proves stable;
  no jitter — crash-looping backend gets hammered at 500 ms by every client in
  lockstep (`frontend/src/ws.ts:20-41`).
- **L2.** Manual-control TOCTOU across the ARM transition: the IDLE check and
  the DIO write are separate device transactions; a concurrent arm lands in
  between, and per-register `FIO*` writes are **not** masked by `DIO_INHIBIT`
  — a valve can be flipped while ARMED (`manual_control.py:29-47`). ~ms window.
- **L3.** Fire-and-forget WS broadcast tasks hold no strong reference — under
  GC pressure an event broadcast can be destroyed mid-flight
  (`node.py:135-136`).
- **L4.** `DeviceManager.switch` restore path can itself fail (old device also
  gone) leaving no stream, a closed backend, and `info()` reporting the old
  mode (`device_manager.py:169-179`).
- **L5.** Rejected LOAD leaves the 2048-byte Lua FIFO allocated and full —
  the exact `SYSTEM_MEMORY_BEREFT` starvation condition documented in
  `docs/t7-lua-stream-fixes.md`; recovery costs an extra FAULT cycle
  (`lua/sequencer.lua:132`).
- **L6.** ARMED-state tick clamp (`x>1000`) drops backlog, delaying
  heartbeat-loss detection by the dropped amount (`lua/sequencer.lua:184`).
- **L7.** Spark guard watches only the sequencer's own commanded word and is
  inactive during ABORTING — spark energized by an abort-table word or manual
  write mid-run is invisible to it (`lua/sequencer.lua:158-160`).
- **L8.** `run_export_csv` "streaming" builds the full run in memory first —
  an 8 h × 50 Hz export is hundreds of MB of Python strings on the Pi, able to
  OOM the *control* node (worse at 1 kHz) (`recorder.py:281-326`).
- **L9.** `GET /api/runs` opens and parses every HDF5 on every call — O(n)
  slow-down as runs accumulate (`recorder.py:222-232`).
- **L10.** `sequence_sha256` on the recorder is stamped from the *last loaded*
  sequence, not the one fired — provenance can be wrong if a load happens
  before run start (`recorder.py:91`, `rest.py:279`).
- **L11.** `SCHEMA_VERSION` is written but never checked on read; malformed
  attrs are silently swallowed → silently-empty run metadata after future
  schema evolution (`recorder.py:169,357-384`).
- **L12.** `connection_read` exposes arbitrary LJM register reads,
  unauthenticated (with H13) (`rest.py:912-921`).
- **L13.** cli/tools edges: `cmd_soak` can crash on a negative sleep at the
  end of an N-hour soak (`cli.py:136-137`); `cmd_deploy_lua`'s failure handler
  can mask the real error if the handle dropped (`cli.py:195-199`); the timing
  report's test 1 can never report PASS and test 4's "timeout observed"
  measures the scripted sleep (`tools/run_timing_report.py:267,407`).
- **L14.** Fire-window end for clean (DONE) runs is unbounded — `seq_terminal`
  is only logged for ABORTED/FAULT, so review-rule `min`/`mean`/`rms` metrics
  fold cooldown data into the fire window (`review.py:43-53`,
  `tools/tbctl_load.py:44-59`, `sequencer.py:264-265`).
- **L15.** Output-only channel maps pass validation, run in sim, and fail at
  `eStreamStart` on hardware (`acquisition.py:157-159`).
- **L16.** Expression/tag grammar mismatch: legal tags like `temp.2nd` can
  never be referenced from a derived expression (`models.py:206` vs
  `expr.py:59-62`); booleans sneak past the "numeric constants only" contract
  (`a.x + True` evaluates). Note: the expr sandbox itself held up under
  adversarial probing — no escape found.
- **L17.** `AnalogInChannel.range` unconstrained (LJM silently coerces
  non-{10,1,0.1,0.01} values); `YAxisConfig`/`warn_min/max` ordering
  unchecked; dashboards never cross-validated against the channel map (panels
  can reference nonexistent tags and 404 per-tag at runtime); `*.yml` config
  files silently ignored by the `*.yaml` glob; malformed checklists silently
  skipped.

## 5. Potential future issues (working today, armed for later)

- **F1. Lua codegen is a hand-maintained subset** (`shared/codegen.py:195-263`):
  `gen_python` iterates the whole register spec; `gen_lua` emits only
  hardcoded key lists. *Adding* a slot to `registers.yaml` produces a Python
  constant with no Lua counterpart and **no check fails** — discovered only
  when debugging on hardware.
- **F2. Wire-format limits triplicated with no cross-check:** `MAX_STEPS=128`
  and 2 ms spacing hardcoded in `models.py:327-329` vs `registers.yaml:117-118`
  (feeds the generated constants) vs the Lua. Editing the declared "single
  source of truth" changes device limits but not model validation. Also: the
  FIFO `allocate_bytes: 2048` is not derived from `max_steps` — beyond 169
  steps the FIFO overflows with no assert linking the two; and the size
  comment at `registers.yaml:78` is wrong on both header size (12 B, not 10)
  and step count (128, not 256).
- **F3. `minify_lua` is a regex, not a tokenizer** (`script_loader.py:43-73`):
  safe only because the current artifact has no strings, block comments, or
  `- -` sequences. A future edit silently corrupts the *deployed* script —
  and nothing (CI or tests) ever executes the minified output. Found by three
  passes.
- **F4. `TICK_MS` is cosmetic** — Lua compares milliseconds directly to tick
  counts; correct only while `tick_ms: 1`. The named constant invites someone
  to change it and silently halve every timing and timeout.
- **F5. `LJ.CheckInterval` return semantics are assumed, not verified:** the
  entire timing/overrun design assumes it returns a count of elapsed 1 ms
  intervals. The test shims bake that assumption in. If firmware returns
  1/true per call, overrun protection is dead and the whole sequence timeline
  silently dilates under load. One hardware measurement settles it (pairs
  with H7).
- **F6. Upper DIO bits (CIO/MIO) unprotected by the Lua path:** `DIO_STATE`
  written as u32 with bits 16-22 = 0 and inhibit upper bits 0 — any future use
  of CIO/MIO as outputs gets clobbered/re-directed on every LOAD
  (`lua/sequencer.lua:64,119`; the comment at 118 mislabels which lines are
  exposed). The HW watchdog config protects the upper 16; the Lua does not.
- **F7. Hardcoded register address `46189` in the purge script**
  (`script_loader.py:33`) — violates the repo's own D10 rule; a slot remap
  makes purge zero an unrelated USER_RAM register.
- **F8. Frontend 1 kHz cliff:** buffers are plain `number[]` with O(n)
  front-`splice` per frame and full-buffer `uPlot.join` + `setData` per panel
  at 10 Hz (`databuf.ts:49-111`, `TimeseriesPanel.tsx:336-345`). At the
  reserved `fast: 1000 Hz` group this is millions of element copies/second on
  the operator console's main thread — GC pauses on the abort button during
  the highest-rate phase of a test. Also: mixed-rate tags on one chart will
  render the slower series as invisible gaps (`uPlot.join` union timebase +
  `points: {show: false}`), and the 1.0 s `isStale` threshold breaks for any
  future ≤1 Hz group.
- **F9. Deployment hardening:** `Restart=on-failure` doesn't cover exit-0 or
  hangs; no systemd `WatchdogSec`; mount dependency is ordering-only
  (`After=` without `RequiresMountsFor=/data/tbctl`) so runs can silently land
  on the SD card; every restart transiently disables the HW watchdog, and a
  crash loop (RestartSec=2) keeps resetting its comm timer so it may never
  fire (`deploy/tbctl-node.service`, `src/tbctl/hw/watchdog.py:39`).
- **F10. HDF5 crash-safety:** no SWMR; hard power loss between a dataset
  resize and flush, or during `stop_run` attr writes, can leave the
  source-of-truth run file structurally inconsistent (`recorder.py:196-218`).

## 6. Test & CI gaps (what the green suite doesn't prove)

- **T1. The operator abort HTTP path (`POST /api/sequences/abort`) has zero
  test coverage** — every abort test calls `sequencer.abort()` directly. A
  routing/serialization regression on the abort button ships green.
- **T2. The spark-force-low check in the Lua harness is tautological**
  (`tests/lua/run_sequencer_tests.lua:386-390`): it reuses a `fire_tick` from
  an earlier scenario and scans the cumulative write log, so any historical
  safe-word write satisfies it — it passes even if the guard is broken.
- **T3. The deployed (minified) Lua is never executed by anything** — CI and
  both harnesses run the unminified source (pairs with F3).
- **T4. Mock/Lua behavioral divergences blind the suite:** synchronous CMD
  processing (hides C1), `dio_inhibit=0xFFFF` boot default (hides C3), no
  OVERRUN semantics (hides H6; the sim's 10 s catch-up is even enshrined by
  `test_lua_sim.py::test_catchup_applies_all_due_steps_in_order`), no
  1-hour step cap (hides M16), spark guard on the electrical image instead of
  the commanded word. `test_lua_sim.py` tests a parallel Python
  implementation, not the device code.
- **T5. Watchdog enforcement is never tested — only its register
  configuration**; the mock has no watchdog model, and the node-startup
  hardware branch (`node.py:140-146`) is never executed by any test.
  `test_watchdog_settings` mostly asserts the values it wrote.
- **T6. Untested Lua paths:** overrun from RUNNING and from ABORTING, the
  `x>1000` clamp, header rejection for `ns/na > MAX_STEPS`, `t>3600000`
  rejection, LOAD-while-not-idle FIFO residue, DONE-state behavior under
  `allow_unsafe_end`. The "truncation" test actually only exercises CRC (the
  dropped byte is padded back to a full word before the length check).
- **T7. No frontend tests at all** (ws reconnect, databuf, store); playwright
  is a dead devDependency.
- **T8. Flake risks:** the sequencer fixture sets `_hb_timeout_ms = 150` for
  *every* test — a >150 ms CI stall spuriously aborts happy-path tests
  (`tests/test_sequencer.py:132`); several wall-clock thresholds have modest
  margins (`test_multirate.py:82`, `test_api_runs.py:47`,
  `test_redlines.py:129-133`).
- **T9. CI gaps:** frontend `dist/` referenced by `docs/deployment.md:57` is
  never uploaded as an artifact; `uv sync` without `--locked`; `tools/`
  unlinted in CI; `test_lua_sequencer.py` silently skips when no Lua
  interpreter is present (an environment without lua5.x ships with zero
  device-code coverage and no failure signal).
- **T10. `tests/test_api.py:16`** builds a context with no `data_dir`, so test
  runs create `./logs/` inside the repo (gitignored; pollution only).

## 7. Verified sound (checked, not bugs)

For the record, the following load-bearing contracts were explicitly
adversarially checked and held up:

- CRC-16/CCITT-FALSE bit-identical between `crc.py`, `crc16.lua`, and the
  inlined sequencer copy; golden vectors + the published `0x29B1` check value
  pass on both sides; CRC coverage (header+steps, trailer excluded) matches.
- Wire format Python↔Lua: field order, LE u16 words, u32 `t_ms` split
  lo-word-first, exact-length check, `STEP_COUNT=(n<<8)|m`, 128-step cap on
  both sides, guard-without-mask rejected on both sides.
- Time units: s (YAML) → ms (exact for t ≤ 600 s) → 1 ms ticks; heartbeat
  ms on both sides; the float32 hazards the authors already knew about
  (line 117) are handled.
- Arm gating: confirm string, control mode, LOADED-state, ARM_CODE magic
  consumed once; manual-control IDLE lockout; abort endpoint takes no body.
- Path traversal: run ids, asset filenames, and config names are all
  regex-anchored; CSV export materializes before streaming (no
  use-after-close).
- The expression sandbox (`expr.py`): AST-walk only, whitelisted calls,
  no attribute access, no escape found under adversarial probing.
- `seq_save` forces `payload["name"] = name` (URL wins), so filename/model
  name can't diverge.
- Shipped `configs/` all load, cross-validate, **and compile** cleanly.
- Frontend↔backend message shapes (`frame`/`seq_status`/`event`) match
  `types.ts`; timestamps consistently epoch-seconds; msgpack keeps float64.
- Generated register constants (Python/Lua) are in sync with
  `registers.yaml`, and check-mode cannot false-pass on stale addresses.

   verify failure.
